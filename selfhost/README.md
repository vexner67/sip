# Sip на Sip

Компилятор Sip переписан на самом Sip и собирает сам себя без Python: нужен
только clang. Каждая часть выдаёт ровно то же, что эталон на Python в
`siplang/`: это проверяет `python3 selfhost/parity.py` (и тест `SelfhostTest`).

| Часть | Python | Sip | Статус |
|---|---|---|---|
| Лексер | `siplang/lexer.py` | `lexer.sip` | готов: токены, позиции и ошибки совпадают |
| Парсер | `siplang/parser.py` | `parser.sip` | готов: дерево и ошибки совпадают |
| Загрузчик модулей | `siplang/modules.py` | `modules.sip` | готов: `import`, `from ... import`, пакеты с `sip.toml` (зависимости-папки), std; git-зависимостей ещё нет |
| Проверка типов | `siplang/checker.py`, `siplang/types.py` | `checker.sip` | готова: типы всех выражений и ошибки совпадают |
| Типы в C | `siplang/cregistry.py` | `creg.sip` | готов: списки, словари, кортежи, записи, JSON, CSV |
| Генерация C | `siplang/cgen.py` | `cgen.sip` | готова: единицы C совпадают байт в байт |
| Сборка | `siplang/compiler.py` | `sipc.sip` | готова: кэш объектных файлов, clang параллельно, компоновка |
| Рантайм | `siplang/native/sip_rt.h` | `siplang/std/rt.sip` | начат: строковые функции и `int(s)`; см. ниже |

## Сборка без Python

Python нужен один раз, чтобы получить первый `sipc`. Дальше `sipc` собирает
сам себя, и C у нового поколения совпадает с C предыдущего:

```bash
python3 -m siplang build selfhost/sipc.sip -o sipc   # первый раз, через Python
./sipc build selfhost/sipc.sip -o sipc               # дальше сам
./sipc run examples/greet.sip Ann
./sipc build examples/word_freq.sip -o wf
./sipc c examples/fib.sip                            # сгенерированный C
```

Стандартную библиотеку и рантайм `sipc` ищет в `--std DIR`, `$SIP_STD` или в
`siplang/std` в текущей папке, папке исходника или их родителях. Объектные
файлы лежат в `~/.cache/sip/obj` (или `$SIP_CACHE`), clang запускается
параллельно по единице на модуль, повторная сборка без правок не вызывает
clang. `sipc run` передаёт программе только позиционные аргументы; для флагов
`--name` соберите бинарник через `sipc build`.

Фронтенд на Sip быстрее Python: исходники самого компилятора (9.8 тысячи строк
с модулями и рантаймом на Sip) он проверяет и переводит в C за 0.09 с, Python за
0.69 с; маленькую программу — за 6 мс против 132 мс (из них около 3 мс — рантайм
на Sip, который подключается к каждой программе; clang компилирует его один раз
и дальше берёт из кэша). Сборка мусора занимает
около четверти этого времени: 3 сборки, 0.03 с (с `SIP_GC=off` — 0.066 с). Графики: [bench/charts.html](../bench/charts.html).

## Рантайм на Sip

Рантайм переехал из C (`siplang/native/sip_rt.h`) в Sip (`siplang/std/rt.sip`)
везде, где это логика, а не обращение к ОС: `sip_rt.h` сократился с 2267 до
1573 строк, `rt.sip` вырос до 1041. Загрузчик подключает `rt.sip` к каждой программе, как
модуль std с префиксом `std__rt__`; коду пользователя его имена не видны.
Генератор C вызывает его функции напрямую (`f_std__rt__str_replace(...)`). Перед
функциями, которые могут бросить ошибку, он ставит `sip_std_line`, поэтому
ошибка указывает на строку пользователя: `prog.sip:3: ParseError: invalid int: 'zz'`.
В раздельной сборке `rt.sip` — своя единица C, одна на все программы, и clang
компилирует её один раз.

На Sip написаны:

- строки: `lower`, `upper`, `isdigit`, `isalpha`, `isspace`, `isalnum`, `isupper`,
  `islower`, `capitalize`, `title`, `count`, `rfind`, `removeprefix`,
  `removesuffix`, `ljust`, `rjust`, `zfill`, `replace`, `strip`, `lstrip`,
  `rstrip`, `str * n`, `ord`, `chr` и `repr` строки;
- числа: `int(s)`, `float(s)` и печать float как в Python (кратчайшая запись,
  которая читается обратно);
- JSON и CSV целиком: лексер, строки с экранированием, числа, пути для ошибок
  (`$.users[0].age`), запись. Код под каждый тип по-прежнему генерирует
  компилятор, но он только вызывает функции `jp_*`, `je_*` и `csv_*` из `rt.sip`;
- разбор аргументов `fn main`: флаги, `--no-флаги`, позиционные, `*rest`, usage;
- перевод регулярных выражений в POSIX ERE (`std/re.sip`).

В C осталось ядро, которое Sip пока не выражает сам:

- примитивы для `rt.sip`: байт строки, кусок без копии, сырая память (`_alloc`,
  `_set`, `_fill`, `_copy`), построитель строк. Границы они не проверяют: их
  вызывает только `rt.sip`;
- то, что генератор вставляет прямо в код: арифметика с проверкой переполнения,
  сравнение, хэши, срезы и склейка строк, буфер `print`;
- сборщик мусора (нужен доступ к стеку и регистрам), ошибки на `setjmp`/`longjmp`
  с печатью при падении и запуском `sip test`, потоки и GIL для `async fn`;
- тонкие обёртки над libc и libcurl: файлы, `os`, время, `strtod`/`snprintf`,
  `regcomp`, HTTP.

Обёртки над libc на третьем этапе станут прямыми вызовами libSystem (так делает
и Go), а вставки генератора — машинными командами. Сборщику мусора и ошибкам
нужны чтение и запись памяти по адресу и доступ к кадру стека; их удобнее
переносить вместе со своим бэкендом, который даст эти примитивы.

По скорости функции на Sip не уступают прежним на C, а местами быстрее:

| | было (C) | стало (Sip) | Python |
|---|---|---|---|
| `json.read` 32 МБ в `[User]` | 80 мс | 48 мс | 179 мс |
| `json.stringify` того же | 547 мс | 147 мс | 142 мс |
| `csv.read` 500 тыс. строк в записи (без сборщика) | 27 мс | 28 мс | 395 мс |
| `csv.write` того же | 320 мс | 197 мс | 207 мс |

Вывод ускорился за счёт печати float: вместо перебора всех точностей (до 17
пар `snprintf` + `strtod` на число) берутся 15 значащих цифр без нулей в конце,
если они читаются обратно, иначе 16 или 17.

Функции на Sip Они написаны так, чтобы
clang мог их векторизовать: `c ^ 32` вместо `c + 32` и `sum(1 for ...)` для
подсчёта, потому что у этих операций нет проверки переполнения. `replace` и
`int(s)` стали быстрее (поиск подстроки теперь через `memchr`), остальные в
пределах шума; бенчмарки `bench/speed` не изменились.

## Команды

```bash
sip run selfhost/lexer.sip FILE.sip    # токены построчно
sip run selfhost/parser.sip FILE.sip   # дерево, узел на строку
sip run selfhost/checker.sip FILE.sip  # дерево с типом каждого выражения или первая ошибка
sip run selfhost/cgen.sip FILE.sip     # единицы C, как их выдаёт siplang/cgen.py
python3 selfhost/parity.py             # сравнение с Python на всех .sip репозитория
python3 selfhost/parity.py --corpus    # собрать программы из набора тестов (~/.cache/sip/selfhost-corpus)
python3 selfhost/parity.py --only checker
python3 selfhost/parity.py --only cgen
```

Проверку типов (вместе с загрузкой модулей) сравнивает тот же `parity.py`: обе
стороны печатают дерево всей программы после проверки, и у каждого выражения
стоит его тип (`Name@3 :: [int]`), либо выводят первую ошибку. Входы: файлы
репозитория, трудные случаи и проекты из нескольких файлов из `parity.py`
(циклический импорт, приватные имена, пакеты, обобщённые типы из модуля, ошибки
в импортированном файле) и программы, которые компилирует набор тестов (среди
них много программ с ошибками типов).

`checker.sip` проверяет сам себя вместе с `modules.sip`, `parser.sip`, `lexer.sip`
и модулями std `os` и `path`: дерево с типами (около 77 тысяч строк) совпадает с
Python, и получается оно примерно в 8 раз быстрее.

В `sip.toml` загрузчик понимает `[package] name` и `[deps]` вида
`kit = "../kit"` или `kit = { path = "../kit" }`; `[c] flags` нужны только
компилятору C. Для git-зависимостей пока есть только сообщение об ошибке.

Дерево в `parser.sip` — один общий узел `N(kind, line, s, kids, ty)`: `kind` — имя
класса из `siplang/nodes.py`, дети идут в порядке его полей. Листья: строка
(`str`), `None`, `bool`, список (`list`) и кортеж (`tuple`). Поля extern-функций
лежат в дополнительном ребёнке `extern`.

`ty` — номер типа узла в таблице проверки типов. Типы в `checker.sip` — тоже один
вид `Ty` с полем `k` (prim, list, tvar, record, ...); тождество объектов Python
заменено номером `id`.

Лексер и парсер разбирают сами себя и весь код репозитория, включая стандартную библиотеку.
